knomit is a distributed, decentralized knowledge base built from facts —
knowledge + commit. This page gets you from zero to a running server with a peer
connected.

## Install

The quickest way in is a signed release build — no toolchain, no compile step.

<CardGrid>
  <Card title="Download a release" icon="download">
    Grab the [desktop app or the server binary](/download) for macOS or Linux.
    The macOS app is notarized and keeps itself up to date; both platforms ship
    a `knomit serve` tarball. **Start here unless you need to modify knomit.**
  </Card>
  <Card title="Build from source" icon="seti:go">
    Everything below. Needed if you're changing knomit itself, or running on a

## Build from source

### Requirements

- **Go 1.25+** — the entire backend.
- **Node.js + npm** — builds the embedded React frontend.
- **Git CLI** — knomit shells out to `git`.
- **A C compiler** — Xcode Command Line Tools on macOS (`xcode-select --install`),
  or `gcc` / `build-essential` on Linux. The build is CGO-based (SQLite and the
  ONNX bindings are compiled in).

<Aside type="note">
Two native shared libraries — **ONNX Runtime** (embeddings) and **graphqlite**
(graph queries) — are downloaded automatically into `dist/<goos>-<goarch>/lib/`
by `make setup` / `make build`. You don't install them by hand. The build also
drops top-level `dist/knomit` and `dist/knomit-bridge` symlinks pointing into
that platform directory.
</Aside>

### Build and run

<Steps>

1. Clone the repository and enter it.

   ```sh
   git clone https://github.com/knomit/knomit.git
   cd knomit
   ```

2. Download the native libraries (one-time).

   ```sh
   make setup
   ```

3. Build the web frontend and the Go binaries.

   ```sh
   make build
   ```

4. Start the server.

   ```sh
   make run
   ```

</Steps>

Open <strong>http://localhost:19278/</strong> for the web UI. A fresh install
starts with **no repositories** — the UI's "no repos" screen is the ordinary
first-run state, not an error. Create your first one from **Manage repos**.

<Aside type="tip" title="Prefer a native app?">
The [desktop app](/docs/desktop/) is a system-tray app that runs the server
in-process and lets MCP clients auto-discover it — no terminal needed to keep
knomit running. Most people should just [download it](/download). To build it
here instead of `make run`, use `make desktop`: on macOS that produces
`dist/darwin-arm64/Knomit.app`; on Linux it produces the `knomit-desktop`
binary only — run `make desktop-install` afterwards for the `.desktop` launcher
and icon.
</Aside>

<Aside type="tip" title="No CLI to create repos">
Repos are created, archived, restored, and purged at runtime through the web UI
("Manage repos") or the [REST API](/docs/api/) — there is no CLI command to
create one, and MCP cannot create repos at all. No repo is privileged: knomit
starts with none, and archiving your last one is allowed (it stays restorable).
Because nothing falls back to a default name, commands that act on a repo make
you name one: `knomit verify` needs `--repo` unless you pass `--all`, and
`knomit-bridge` needs exactly one of `--repo` or `--lens`.
</Aside>

## Connect an agent over MCP

The simplest setup uses `knomit-bridge` over stdio — it auto-discovers your
agent branch from the running server, so you never look it up by hand.

<Tabs>
  <TabItem label="Claude Code (.mcp.json)">

  ```json
  {
    "mcpServers": {
      "knomit": {
        "command": "dist/knomit-bridge",
        "args": ["--repo", "core"]
      }
    }
  }
  ```

  To read across several repos at once, use a [lens](/docs/lenses/) instead:
  `"args": ["--lens", "<lens-name>"]`. `--lens` and `--repo` are mutually
  exclusive — passing both is a fatal error.

  </TabItem>
  <TabItem label="Streamable HTTP">

  Connect directly, substituting the branch logged on startup (`/` → `:` in the
  URL path):

  ```json
  {
    "mcpServers": {
      "knomit": {
        "type": "streamable-http",
        "url": "http://localhost:19278/api/v1/repos/core/branches/agent:hostname-abc123/mcp"
      }
    }
  }
  ```

  A [lens](/docs/lenses/) has no branch segment — its URL is
  `http://localhost:19278/api/v1/lenses/<lens-name>/mcp`.

  </TabItem>
</Tabs>

<Aside type="tip" title="Let the bridge write this for you">
`knomit-bridge claude init` scaffolds the Claude Code integration into the
current directory: the `.mcp.json` above, `.claude/settings.json`, eleven
`/knomit-…` skills, and a block appended to `CLAUDE.md`. Where one of those
already exists it drops a companion file beside it rather than overwriting your
version. See [Claude Code](/docs/claude-code/).

The tools are usable without any of it — their descriptions carry the guidance a
model needs to call them correctly. What the skills and the `CLAUDE.md` block add
is *when* to reach for them: recall before touching an unfamiliar area, record a
decision once it is made, re-verify a fact before relying on it.
</Aside>

## Write your first fact

With an agent connected, ask it to remember something. Under the hood it calls
`knomit_learn`, which writes a markdown fact and commits it:

```markdown
---
type: observation
confidence: 0.8
domain: [music]
entities: [alice]
refs:
  - src://myrepo/src/preferences.ts@abc1234
---
Alice prefers rock music over jazz.
```

That write is one atomic, signed git commit on your agent's branch. Browse it in
the web UI, or query it back with `knomit_query`.
